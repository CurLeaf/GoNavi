先红后绿。根因没查清不准改；没有先失败的测试不准写实现；没有本轮命令输出不准说做完。

本层不 commit。已经先写了实现再补测试：删掉实现，从失败测试重来；不许留着当参考，不许边看边改。

## 回合

根因、失败测试、最小改动压在 **1～3 批工具**。排障 8 步本回合过完，不要一步一轮。

落盘按 AGENTS：绑定层保持薄、驱动特有能力用可选接口、文案走 `shared/i18n`、禁止手改 `frontend/wailsjs/`、禁止膨胀超标文件、不绕过只读连接与生产库确认。没按规范写 = 没做完。

## 范围

只改用户消息或方案任务用 `@path` 点名的文件。有并行泳道时不要碰其他泳道。做完回：diff 范围 + 验证命令全文。

测试与被测文件同目录：Go 用 `go test ./<包> -count=1`（`foo.go` → `foo_test.go`）；前端用 Vitest（`foo.ts` → `foo.test.ts` / `.test.tsx`）。

## 排障

修 bug、测试失败、意外行为时先走本节，再进循环。症状补丁算失败。

1. **读证据**：报错、栈、行号、退出码、本轮命令全文。不要略过 warning。
2. **复现**：稳定复现再改；复现不了就先收集，不猜。
3. **看近因**：本轮 diff、近期提交、配置 / 环境差异。
4. **对照能跑的**：同仓里类似且正常的写法，列出每一处差异，不要假定「那无关」。
5. **定位**：坏值从哪进来，沿调用往上追到源。多层（UI → Wails 绑定 → 领域包 → 驱动）在边界看进出数据，先标哪一层断。
6. **一条假设**：写清「我认为 X 是根因，因为 Y」。只改一个变量验证。错了换假设，不要叠补丁。
7. **再进循环**：用失败测试钉住根因，做最小修复。
8. **连修 3 次仍坏**：停，先跟用户说。多半是架构或耦合问题，不要第 4 次盲改。

赶时间、看起来简单、已经猜过几次，更要走完上面。

## 循环

一条行为一个测试。名字说清行为。测真代码，非不得已不 mock。

1. **红**：写最小失败测试，跑对应 `go test` / `npx vitest run`。必须是断言失败（缺功能），不是语法错误。立刻通过 = 测到了旧行为，改测试。
2. **绿**：只写让这个测试通过的最少代码。不顺手加功能、不改旁路。
3. **再跑**：本测试与相关旧测试都通过，输出干净。失败改实现，不改测试迁就。
4. **重构**：只在绿之后。去重、改名、抽函数。行为不变，保持绿。
5. 下一条行为，再从红开始。

修 bug：排障查清后，先写能复现的失败测试再改。没见过红的回归测试不算数。

卡住：不会测 → 先写期望 API 和断言；测试很复杂 → 设计太复杂，简化接口；必须处处 mock → 耦合过重。

| | 好 | 坏 |
|---|---|---|
| 粒度 | 一件事；名字里有「和」就拆 | 一次测三件事 |
| 名字 | 说清行为 | `test1`、`works` |
| 对象 | 真行为 | 断言 mock 被调用了几次 |

## 收口闸

说通过 / 做完 / 修好之前：

1. 确定哪条命令能证明这句话
2. **本轮**完整跑完，不用上一轮记忆
3. 读完全文、看退出码、数失败
4. 输出对得上才说；对不上就报告实际状态
5. 有方案则逐条对任务，不要只说「测试过了」

验证对齐 `AGENTS.md`：有测试先跑 `go test ./<包> -count=1` 或 `cd frontend && npx vitest run <文件>`。未触及全仓或发布契约时，不要加跑 `go test ./...` / `wails build`。

改了页面、样式或用户可见行为时，收口走浏览器工具（无头）：打开 → 等待或快照 → 必要时看控制台。禁止有头抢焦点、禁止点击会写入的按钮。用户说「打开给我看」才允许可见窗口。

| 宣称 | 要有 | 不够 |
|---|---|---|
| 测试通过 | 本轮测试命令，0 失败 | 「应该过了」 |
| 构建成功 | 构建命令 exit 0 | lint 过了 |
| bug 已修 | 原症状的测试 / 复现步骤通过 | 改了代码 |
| 回归测试有效 | 见过红再绿 | 测试绿过一次 |
| 需求齐了 | 对照方案逐条 | 测试绿了就算 |
| 泳道做完 | diff 落在点名文件 + 命令输出 | 会话说「成功」 |

提交不是本闸的事。

## 红灯

立刻停：代码写在测试前；测试立刻绿；说不清刚才为什么红；should / probably / 看起来行；先报喜再跑命令；「精神对了就行」「留着当参考」「这次例外」；没复现、没假设就改；一次叠多个补丁；连修 3 次仍坏还继续盲改。

## 例子

空查询被当成成功：红 `rejects empty query` → `go test …` → `Success=true`，期望 `false`；绿：空查询返回 `Success: false` + i18n `Message` → 再跑 → PASS；重构：同类校验抽到已有 helper。修好后把该命令输出放进回复。
